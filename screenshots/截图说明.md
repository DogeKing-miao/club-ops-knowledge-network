## 二、查询场景截图（7 张）

### `04-场地冲突.png` · F8 场地冲突检测
```cypher
MATCH (a1:Activity)-[:HELD_AT]->(v:Venue)<-[:HELD_AT]-(a2:Activity)
WHERE a1.date = a2.date AND a1.activityId < a2.activityId
RETURN v.name AS 场地, a1.date AS 冲突日期, a1.name AS 活动一, a2.name AS 活动二,
       '同一天同一场地，需要改期' AS 建议;
```
**结果**：1 行 —— 东区操场 ｜ 2025-10-18 ｜ 秋季观星夜 ｜ 校园人像外拍 ｜ 同一天同一场地，需要改期

> A04 夜跑打卡周也在东区操场，但日期是 2025-11-10，不构成冲突，所以只有 1 行。

### `05-招新转化.png` · F9 招新转化
```cypher
MATCH (s:Student)-[ap:APPLIED_TO]->(r:Recruitment {recruitId:'R01'})-[:FOR_CLUB]->(c:Club)
WHERE NOT (s)-[:MEMBER_OF]->(c)
RETURN s.name AS 学生, s.major AS 专业, ap.status AS 申请状态, c.name AS 社团
ORDER BY 学生;
```
**结果**：2 行 —— 李思远 ｜ 哲学 ｜ 待审核 ｜ 星野天文社；周雨桐 ｜ 汉语言文学 ｜ 待审核 ｜ 星野天文社

> 中文按 Unicode 码位排序，所以很可能「周雨桐」在第一行 —— 不影响结论，看「学生 / 申请状态 / 社团」三列即可。

### `12-报名未签到.png` · F6 报名与签到对不上
```cypher
MATCH (a:Activity {activityId:'A01'})<-[r:SIGNED_UP]-(s:Student)
OPTIONAL MATCH (s)-[att:ATTENDED]->(a)
RETURN a.name AS 活动, s.name AS 学生, r.status AS 报名状态,
       CASE WHEN att IS NULL THEN '报名未到' ELSE '已签到' END AS 签到情况
ORDER BY 签到情况 DESC, 学生;
```
**结果**：4 行 —— 林一舟、赵敏为「已签到」；陈嘉禾、王梓涵为「报名未到」

> 对应数据钩子 H6：A01 报名 4 人、实际签到 2 人。

### `13-报名者筛选.png` · F33 报名者筛选与匹配
```cypher
MATCH (r:Recruitment {recruitId:'R01'})-[:FOR_CLUB]->(c:Club)
MATCH (s:Student)-[:APPLIED_TO]->(r)
OPTIONAL MATCH (s)-[:HAS_TAG]->(g:InterestTag)<-[:TAGGED_WITH]-(c)
RETURN s.name AS 报名学生, s.major AS 专业,
       collect(DISTINCT g.name) AS 命中标签,
       count(DISTINCT g) AS 匹配度

```
**结果**：2 行 —— 李思远 ｜ 哲学 ｜ `["天文观测"]` ｜ 匹配度 **1**；周雨桐 ｜ 汉语言文学 ｜ `[]` ｜ 匹配度 **0**

## 三、业务动作前后对比（6 张）

> 三个动作各拍「执行前 / 执行后」一张。这三组图看的是在册人数、剩余名额与成员状态，与 C04 补漏无关。

### `06-动作1前.png` / `07-动作1后.png` · F11 李思远加入星野天文社

**执行前**
```cypher
MATCH (s:Student {studentId:'S005'}) WITH s, size([(s)-[:MEMBER_OF]->(c:Club) | c]) AS 社团数
OPTIONAL MATCH (s)-[m:MEMBER_OF]->(c:Club)
WITH s, 社团数, collect(c.name) AS 已加入社团
RETURN s.name AS 学生, 已加入社团, 社团数,
       COUNT { (x:Student)-[mm:MEMBER_OF]->(cc:Club {clubId:'C01'}) WHERE mm.status='在册' } AS 星野天文社在册人数;
```
→ 李思远 ｜ `[]` ｜ 0 ｜ 在册人数 **3**

**执行**
```cypher
MATCH (s:Student {studentId:'S005'})-[ap:APPLIED_TO]->(:Recruitment)-[:FOR_CLUB]->(c:Club {clubId:'C01'})
MERGE (s)-[m:MEMBER_OF]->(c)
SET m.role = '成员', m.joinDate = date(), m.status = '在册', ap.status = '已通过';
```
→ Created 1 relationship, set 4 properties

**执行后**
```cypher
MATCH (s:Student {studentId:'S005'})
RETURN s.name AS 学生,
       [(s)-[mm2:MEMBER_OF]->(cc2:Club) | cc2.name + '·' + mm2.role + '·' + mm2.status] AS 加入明细,
       COUNT { (x:Student)-[mm:MEMBER_OF]->(c:Club {clubId:'C01'}) WHERE mm.status='在册' } AS 星野天文社在册人数;
```
→ 李思远 ｜ `[星野天文社·成员·在册]` ｜ 在册人数 **4**（3 → 4 ✓）

### `08-动作2前.png` / `09-动作2后.png` · F12 郑亦航报名秋季观星夜

**执行前**
```cypher
MATCH (a:Activity {activityId:'A01'})
RETURN a.name AS 活动, a.capacity AS 总名额, a.remaining AS 剩余名额, a.status AS 状态,
       COUNT { (s0:Student)-[:SIGNED_UP]->(a) } AS 已报名人数;
```
→ 秋季观星夜 ｜ 40 ｜ 剩余 **36** ｜ 报名中 ｜ 已报名 4

**执行**
```cypher
MATCH (s:Student {studentId:'S008'}), (a:Activity {activityId:'A01'}) WHERE a.remaining > 0
MERGE (s)-[r:SIGNED_UP]->(a)
ON CREATE SET r.signedAt = datetime(), r.status = '已报名', a.remaining = a.remaining - 1;
```
→ Created 1 relationship, set 3 properties（另有 `03N90 Cartesian product` 提示，属此写法正常提示）

**执行后**
```cypher
MATCH (a:Activity {activityId:'A01'})<-[r:SIGNED_UP]-(s:Student)
RETURN a.name AS 活动, a.remaining AS 剩余名额, count(s) AS 报名人数, collect(s.name) AS 报名名单;
```
→ 剩余名额 **35**（36 → 35 ✓），报名 5 人：`["林一舟","赵敏","陈嘉禾","王梓涵","郑亦航"]`

### `10-动作3前.png` / `11-动作3后.png` · F14 王梓涵退出拾光摄影社

**执行前**
```cypher
MATCH (s:Student {studentId:'S004'})-[m:MEMBER_OF]->(c:Club {clubId:'C03'})
RETURN s.name AS 学生, c.name AS 社团, m.status AS 状态, toString(m.joinDate) AS 入社时间,
       COUNT { (x:Student)-[mm:MEMBER_OF]->(c) WHERE mm.status='在册' } AS C03在册,
       COUNT { (y:Student)-[nn:MEMBER_OF]->(c) WHERE nn.status='已退出' } AS C03已退出;
```
→ 王梓涵 ｜ 拾光摄影社 ｜ 在册 ｜ 2023-10-11 ｜ 在册 **3** ｜ 已退出 0

**执行**
```cypher
MATCH (s:Student {studentId:'S004'})-[m:MEMBER_OF]->(c:Club {clubId:'C03'})
SET m.status = '已退出', m.quitDate = date();
```
→ Set 2 properties

**执行后**
```cypher
MATCH (s:Student)-[m:MEMBER_OF]->(c:Club)
RETURN c.name AS 社团,
       count(CASE WHEN m.status='在册' THEN 1 END) AS 在册成员,
       count(CASE WHEN m.status='已退出' THEN 1 END) AS 已退出
ORDER BY 社团;
```
→ 拾光摄影社 在册 **2** / 已退出 1 ✓；星野天文社 在册 4 / 已退出 1 ✓

> **关系没有删除**，`MEMBER_OF` 仍然存在，只是 `status` 变了 —— 这正是 F14 要演示的点（保留历史，不做物理删除）。

## 附：一个关键说明（为什么这里的语句和手册里不完全一样）

这个版本的 Neo4j Browser 在**一次提交多条语句**时，结果卡片会折叠成「摘要行」，表格看不到。

所以「先……再……」式的两段对照，在这里合并成**一条语句**（用 `COUNT { }` 子查询 / 列表推导），保证「语句 + 结果表」同框。Cypher 语义与 `cypher\` 下的脚本完全一致，只是写法合并了。

同理，本文档每条语句都是**一条可独立执行的完整 Cypher**，单独粘、单独跑、单独截。
